## 一、背景

奉主权人 2026-10-05 令「尽快开始基于 SDD 规范驱动开发」。总线载首份内容 spec 已由 k3-main 席候批（通告 #32）；本席不另起内容 spec，补位母规范层：定目录契约、spec 模板、质量闸、审批门禁与版本追踪，使后续一切 spec 有章可循。

## 二、术语与风格锚点

- SDD（Spec-Driven Development，规范驱动开发）：一切实现以书面规范为先导，规范未定稿不动工。
- 公文风格锚点：《党政机关公文处理工作条例》（中办发〔2012〕14 号），全文页 URL 原样登记于关联锚点，零改动；拟制程序（起草、审核、签发）对位本规范第四节生命周期。
- 文书纪律：现行 govdoc-compliance-ops 三闸（术语闸、格式闸、协议闸）与党组纪律程序检查单五项，全部 spec 文件适用。

## 三、目录契约

```text
sdd/
├── SDD流程规范_母规范_v0.1.0.md   （本件）
└── specs/
    └── NNNN_主题名/
        ├── spec.md      （规范正身：目标、范围、验收准则）
        ├── plan.md      （实施计划，候批后立）
        └── tasks.md     （任务拆解，批准后分解）
```

- 编号四位递增，不回收；一名一目录，不并置。
- 每目录必备 spec.md；plan.md 与 tasks.md 非候批通过不得建立实质内容。

## 四、spec 生命周期（对位公文拟制与办理程序）

1. 起草：依第八节模板成稿，标「草案候批」。
2. 审核：过双闸（otl_source_lint 零 error；govdoc_precheck 零 error），预检报告随稿附。
3. 签发：主权人批准为唯一签发口；批准前任何实现性动作禁止。
4. 办理：批准后转 plan.md、tasks.md；执行留痕入 ops_trace 序列。
5. 归档：完结 spec 状态改「收口」，入 verifier 索引，不删改原文。

## 五、质量闸（双闸联动，强制）

- 格式闸：otl_source_lint.py，零 error 方许送审。
- 术语闸：govdoc_precheck.py，零 error 方许送审；warning 逐条处置并留痕。
- 引用纪律：凡外部数值与事实，须有可核来源；抓取受限者「列入书目不引文」，不以记忆转述充来源。

## 六、审批门禁

- 内容 spec、总线写操作、本机侧动作（A 盘迁移、桌面整理、文件上传）一律逐次显式批准，不先斩后奏。
- 母规范修订同此门禁：改本件须主权人批准。

## 七、版本追踪

- 每轮执行入 verifier/runs/ 时间戳日志；验收准则版本化（verifier/v1、v2…），只增不改。
- spec 文本改动只进不退：新版本件并行存档，旧件标「被 vX 取代」。

## 八、spec.md 模板（强制骨架）

1. 文档头六要素表（标识、版本、状态、日期、责任席、关联锚点）。
2. 目标与非目标。
3. 范围与边界（含不可触碰面）。
4. 验收准则（可机检表述优先）。
5. 风险与挂账。
6. 变更记录。
